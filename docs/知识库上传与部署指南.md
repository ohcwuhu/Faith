# 知识库上传与部署指南

> 面向「换一台机器 / 交给队友 / 部署到服务器 / 重新克隆仓库」这些场景。
> 原理与效果数据见 [知识库检索方案.md](./知识库检索方案.md)。

---

## 一、先说结论

1. **电子书不上传 GitHub**——15 本都是正式出版物，语料是非官方电子版，公开仓库分发
   属于侵权（文件开头就写着"请勿做商业用途"）；
2. **索引 `kb_index.pkl` 也不上传**——它把原文片段烤进去了，同样是版权内容，
   已在 `.gitignore` 里排除；
3. **运行时只需要 `data/kb_index.pkl`**（约 17 MB）。带上它检索立刻可用；
   不带也能启动，只是每轮通话静默不带参考资料，**不报错**。

## 二、知识库由三部分组成

| 组成 | 位置 | 是否进仓库 | 作用 |
| --- | --- | --- | --- |
| 语料源文件 | `<仓库祖父目录>/心理教练智能体知识库-精选15本/` | 否 | 内容本体（15 本 .md） |
| 检索索引 | `backend/data/kb_index.pkl` | 否（已 gitignore） | 运行时实际读取的东西 |
| 构建与检索代码 | `app/services/ai_lab/kb_service.py`、`scripts/build_kb_index.py` | 是 | 建索引 / 查索引 |

三者关系：

```
语料源文件  ──(build_kb_index.py，一次性，约 9 秒)──▶  data/kb_index.pkl
                                                          │(运行时只读)
                                                          ▼
                              kb_service.context_block_smart() ──▶ Dify
```

## 三、从零准备知识库（4 步）

### 1. 放语料

把书的 `.md` 文件放进源目录。默认位置：

```
项目2.0/
├── MindBasic-backend/                     ← 后端仓库
└── ..                                     ← 往上一级
    └── 心理教练智能体知识库-精选15本/       ← 默认扫这里
```

即**后端仓库往上两级的那个目录**下的同名文件夹。

文件名里含 **合并 / 合集 / 汇总 / 整理版 / 全本 / 全集** 的文件会被自动跳过
（这类文件是单册的拼接，一起索引会造成重复命中），构建时会打印跳过了哪些。

### 2. 构建索引

```bash
cd MindBasic-backend
python scripts/build_kb_index.py
```

正常输出：

```
书籍 15 本
跳过重复内容文件 1 个：
  - 心理教练智能体知识库-精选15本（合并版）.md
片段 6,992 条
词条 51,969 个
耗时 8.8s
索引文件 17.3 MB → .../backend/data/kb_index.pkl
```

### 3. 验证检索

```bash
python scripts/build_kb_index.py --query "一躺下就想工作的事，睡不着"
```

会打印命中的书名、章节与片段开头。**有命中才算成功。**

### 4. 确认后端加载

启动后端，日志里应出现：

```
知识库索引已加载：6992 片段 / 51969 词条
```

没出现就说明路径不对或没构建，此时检索返回空（不报错）。

## 四、目录不按默认放怎么办

两个环境变量可以覆盖：

| 变量 | 说明 |
| --- | --- |
| `KB_SOURCE_DIR` | 语料源目录（构建时用） |
| `KB_INDEX_PATH` | 索引输出/读取路径（构建与运行时都用） |

示例：

```bash
set KB_SOURCE_DIR=D:\books\心理教练
python scripts/build_kb_index.py --source D:\books\心理教练
```

## 五、本地运行

```bash
cd MindBasic-backend
python scripts/build_kb_index.py     # 只需一次
python scripts/run_dev.py
```

## 六、Docker 部署

索引有两种进容器的方式，两种都已配好：

| 方式 | 配置位置 | 说明 |
| --- | --- | --- |
| 打进镜像 | `Dockerfile` 的 `COPY data ./data` | 镜像自带索引，适合正式部署 |
| 卷挂载 | `docker-compose.yml` 的 `./data:/app/data` | 宿主机构建、容器直接用，适合边调边跑 |

⚠️ **两个前提**：

1. **先在宿主机构建索引再 build**。全新克隆的仓库里没有 `kb_index.pkl`
   （它被 gitignore 了），直接 `docker compose up --build` 会得到一个「没有知识库」的镜像。
2. **容器内无法构建索引**。语料源目录在 Docker 构建上下文之外（`backend/` 的同级），
   容器里既没有书，`parents[5]` 的默认路径也不成立。要么在宿主机构建后拷进去，
   要么把语料放进 `backend/` 再在镜像里构建。

标准流程：

```bash
cd MindBasic-backend
python scripts/build_kb_index.py        # 宿主机构建
docker compose up -d --build            # 索引随镜像/挂载进容器
docker compose logs backend | findstr 知识库   # 确认已加载
```

## 七、换机器 / 交给队友

| 场景 | 需要带走的东西 |
| --- | --- |
| 只要跑起来 | 代码 + `data/kb_index.pkl`（17 MB） |
| 需要改语料 | 代码 + 语料目录 + 跑一次构建 |

## 八、增删书籍之后

1. 把书放进源目录（或删掉）；
2. 重新跑 `python scripts/build_kb_index.py`；
3. **重启后端**——索引在进程内有缓存，不重启还是旧索引。

判断有没有生效：看启动日志的「片段数」有没有变。

## 九、怎么确认检索真的生效

三档判据，从弱到强：

1. 后端日志出现 `[1/5] 知识检索命中 N 字参考资料`；
2. `python scripts/check_dify.py` 里 `[1/3] 本地知识库命中 N 条`；
3. **回复内容体现书里的说法**——这是唯一硬判据。
   可以临时往 `knowledge_context` 里塞一句带独特词的要求（例如「必须包含"青苔小屋"」），
   看模型会不会照做；会，就说明资料确实进了提示词。

## 十、排障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 日志 `知识库索引不存在` | 没构建，或路径不对 | 跑构建脚本；或设 `KB_INDEX_PATH` |
| 构建报 `知识库目录不存在` | 源目录位置不对 | 用 `--source` 或设 `KB_SOURCE_DIR` |
| 检索总是 0 命中 | 语料没进去 / 书籍被误跳过 | `--query` 手测；看构建输出里跳过了哪些文件 |
| Docker 里没有参考资料 | 镜像没带 `data/`，或没挂卷 | 见第六节 |
| 重建后结果没变 | 进程内缓存 | 重启后端 |
| 同一段内容重复命中 | 合并版/合集被索引了 | 确认文件名含「合并」等标记会被跳过 |
